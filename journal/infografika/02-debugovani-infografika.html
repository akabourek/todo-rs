Pauza na dálkovém

Normálně program proletí od začátku do konce za zlomek sekundy a ty vidíš jen výsledek. Debugger je dálkové ovládání: program zastavíš na zvoleném řádku (breakpoint), podíváš se, co je v proměnných, a pak ho posouváš po jednom kroku.

2 let list = ["Apple", …]; 10 for (index, entry) in … 11 ●println!("{}: {entry}", … 14 println!("Count: {}", … index = 1 · entry = "Banana"
▶F5 ⤼F10 ↓F11 ■⇧F5
1Breakpoint zastaví před řádkem.Žlutý řádek se ještě neprovedl. Co vypíše, uvidíš až po dalším kroku.
2Ladí se debug build.cargo build bez --release obsahuje mapu „strojový kód ↔ řádek“. Bez ní debugger netuší, kde je.
3dbg! je lešení.Rychle ukáže hodnotu, ale do hotového kódu nepatří. Po vyladění ho smaž.

Ty mačkáš tlačítka ve VS Code. Program ve skutečnosti zastavuje a čte LLDB a CodeLLDB mezi nimi tlumočí.

Dálkové ovládání, přijímač, přehrávač, film. Každá vrstva umí jednu věc. Rust k tomu nic zvláštního nepotřebuje, LLDB rozumí i C a C++.

Potřebná rozšíření: rust-analyzer (rady, doplňování, formátování) a CodeLLDB (ladění). CodeLLDB si LLDB přiveze s sebou.

Debug vs release: cargo build = rychlý překlad + ladicí informace (target/debug/). cargo build --release = optimalizace, které řádky přeskládají, takže krokování by skákalo divně.

Dva způsoby spuštění: F5 podle launch.json, nebo nad fn main kliknout na ▶ Debug, které tam ukazuje rust-analyzer.

Návod pro F5: launch.json

.vscode/launch.json
"version": "0.2.0"verze formátu, vždy stejná
"name": "Debug executable 'todo'"jméno v roletce Run and Debug
"type": "lldb"použij CodeLLDB

"terminal": "integrated"výstup i vstup z klávesnice v terminálu
"sourceLanguages": ["rust"]Vec, String čitelně, ne jako surová paměť

Oranžové řádky jste dopsali ručně. Zbytek vygeneroval CodeLLDB z Cargo.toml.

Recept, podle kterého VS Code po stisku F5 program připraví a pustí.

Vytvoření: Ctrl+Shift+D (Run and Debug) → create a launch.json file → LLDB.

{
    "klic": "hodnota",       // dvojice oddělené čárkou

3

Breakpoint: stopka na řádku

F9 · klik vlevo od čísla
2 let list = ["Apple", "Banana", "Cherry"];
4 println!("====== My ToDo List ======");
10 for (index, entry) in list.iter().enumerate() {
11 println!("{}: {entry}", index + 1);
12 }
14 println!("Count: {}", list.len());
TERMINAL ====== My ToDo List ====== ← „1: Apple“ tu ještě není

Program stojí na žlutém řádku 11 v prvním průchodu cyklem. Řádek se ještě neprovedl, proto v terminálu chybí 1: Apple.

Stopka na silnici. Auto zastaví před čárou, ne za ní.

  • Přidat / odebrat: klik vlevo od čísla řádku, nebo kurzor na řádek a F9. Objeví se červená tečka.
  • Breakpoint v cyklu zastaví při každém průchodu. F5 (Continue) doběhne k dalšímu zastavení.
  • Podmíněný breakpoint: pravý klik na tečku → Edit Breakpoint → výraz, např. index == 1. Zastaví jen ve 2. průchodu (index se počítá od 0).
  • Na prázdném řádku nebo komentáři není žádný kód. Debugger takový breakpoint obvykle posune na nejbližší další řádek s kódem.

Krokování: přes, do, ven

F10 · F11 · Shift+F11 · F5
main
let tasks = vec![...];
print_tasks(&tasks); ← jsi tu
println!("Done…");
fn print_tasks(tasks)
for task in tasks {
println!(…);
}
F10 Step Overprovede celé print_tasks(&tasks) najednou a zastaví na println!("Done…")
F11 Step Intovleze dovnitř print_tasks na jeho první řádek
⇧F11 Step Outzevnitř funkce: dokončí ji a vrátí se do main za volání
F5 Continuepusť program naplno až k dalšímu breakpointu (nebo do konce)

Funkci print_tasks v lekci 02 ještě nemáš (přibude v lekci 05). Krokování je ale nejlíp vidět právě na volání funkce.

Výtah v domě funkcí. F10 projede patrem dál, F11 sjede o patro níž do volané funkce, ⇧F11 vyjede zpátky nahoru.

Kdy co: většinou F10. F11 jen tam, kde tě zajímá, co se děje uvnitř tvé funkce.

pozorF11 na řádku s println! vleze do vnitřností standardní knihovny (std::io::_print…). To není tvůj kód. Vrátíš se přes ⇧F11.

Ukončení: ⇧F5 zastaví ladění, Ctrl+⇧F5 program spustí znovu od začátku.

Bez debuggeru: dbg!

dbg!(výraz)
let x = dbg!(2 + 3);
dbg!(&list);
for (index, entry) in list.iter().enumerate() {
    dbg!(index);
    …
}
$ cargo run [src/main.rs:3:13] 2 + 3 = 5 [src/main.rs:4:5] &list = [ "Apple", "Banana", "Cherry", ] [src/main.rs:6:9] index = 0 1: Apple [src/main.rs:6:9] index = 1 2: Banana

Skutečný výstup z cargo run. [soubor:řádek:sloupec] výraz = hodnota. Oranžové řádky jdou na stderr, bílé z println! na stdout.

Lísteček „tady jsem byl a tohle jsem viděl“. Rychlejší než spouštět debugger, ale program se nezastaví.

  • ! = makro, jako println!.
  • Na rozdíl od println! vypíše i kde (soubor, řádek, sloupec) a jaký výraz. Nemusíš psát popisek.
  • Hodnotu vrací dál, takže jde vložit doprostřed výrazu: let y = dbg!(x * 2) + 1;.
  • dbg!(&list) s &: jen si půjčí. Bez & by si list vzal a dál by nešel použít (lekce 05).
  • Píše na stderr, takže se nemíchá do výstupu, který by se přesměroval do souboru.

Editor, který uklízí sám

.vscode/settings.json
celý projekt (nejvyšší úroveň) "rust-analyzer.check.command": "clippy"
"[rust]": { … } jen pro soubory .rs "editor.formatOnSave": true "editor.defaultFormatter": "rust-lang.rust-analyzer" "rust-analyzer.check.command": "clippy"

Škrtnutý řádek je chyba, na kterou jste narazili. Uvnitř "[rust]" ho VS Code ignoruje.

Dvě krabice do sebe. Velká platí pro celý projekt, malá "[rust]" jen pro soubory .rs.

{
    "rust-analyzer.check.command": "clippy",
    "[rust]": {
        "editor.formatOnSave": true,
        "editor.defaultFormatter": "rust-lang.rust-analyzer"
    }
}
  • formatOnSave: Ctrl+S rovnou naformátuje kód (= cargo fmt).
  • check.command = clippy: rady clippy se ukážou v editoru po uložení, ne až po cargo clippy.
  • Workspace nastavení (.vscode/settings.json) platí jen pro tento projekt a má přednost před User nastavením.
ignorovánoDo jazykového bloku "[rust]" patří jen nastavení editoru, která jdou měnit po jazycích (formátování, odsazení…). Nastavení rozšíření jako rust-analyzer.* patří na nejvyšší úroveň.

Hřiště: odlaď svůj program z lekce 02

Klikni vlevo od čísla řádku a přidej breakpoint (červená tečka). Pak ▶ Start/Continue a krokuj. Vedle kódu sleduj proměnné, Watch, Call Stack a terminál. Tlačítka odpovídají klávesám ve VS Code.

Zkus: breakpoint na řádek 11 → Start → několikrát Continue a sleduj, jak se mění index a entry. Pak zapni podmínku index == 1. Nakonec bez breakpointů: Start → program proletí celý.
