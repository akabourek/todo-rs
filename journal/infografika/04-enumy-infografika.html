todo-rs · lekce 04 · enumy a match

Která přihrádka?

Hodnota enumu je žeton, na kterém je napsaná právě jedna varianta. match je třídička: žeton propadá přihrádkami shora dolů a zapadne do první, která mu pasuje. if let je třídička s jedinou přihrádkou. A Option je krabice, ve které něco je (Some), nebo je prázdná (None). Rust tě nenechá sáhnout dovnitř, dokud se nepodíváš.

TaskStatus::Done
ToDo=>' '
InProgress=>'~'
Done=>'X'
Canceled=>'C'
1Hodnota enumu je vždy právě jedna varianta.Úkol je ToDo, nebo Done. Nikdy obojí, nikdy nic.
2match musí mít přihrádku pro každý žeton.Chybí-li větev, kompilátor kód odmítne (E0004).
3Žádný null. „Možná nic“ je Option.Než sáhneš na hodnotu, musíš obsloužit i prázdnou krabici None.

Enum: přepínač s pevnými polohami

enum TaskStatus
enum: vždy svítí právě jedna
ToDoInProgressDoneCanceled
dva bool: čtyři kombinace
done: falsedone: true in_progress: falsečekáhotovo in_progress: truerozpracovánoNESMYSL

Se dvěma bool jde zapsat úkol „hotový a zároveň rozpracovaný“. Enum takový stav vůbec nemá, takže ho nejde ani omylem vytvořit.

Přepínač na pračce: poloh je pevný počet a knoflík stojí vždy právě v jedné.

#[derive(Debug)]
enum TaskStatus {
    ToDo,          // varianty: PascalCase, za každou čárka
    InProgress,
    Done,
    Canceled,
}

let s = TaskStatus::Done;

Jak číst ::: „z“. TaskStatus::Done = varianta Done z typu TaskStatus. Stejně jako Task::new = funkce new z typu Task.

:: vs .: dvojtečky sahají do typu (varianta, asociovaná funkce), tečka do hodnoty (pole task.title, metoda task.start()).

match: třídička

vzor => výraz,
TaskStatus::InProgress
match self.status {
TaskStatus::ToDo=>' '
TaskStatus::InProgress=>'~'
TaskStatus::Done=>'X'
TaskStatus::Canceled=>'C'
symbol() vrátí '~'

Žeton zkouší přihrádky shora dolů. Zapadne do první, která pasuje, a další už nezkouší.

Třídička na mince: každá mince propadne otvorem, do kterého se vejde, a na druhé straně vypadne výsledek.

fn symbol(&self) -> char {
    match self.status {
        TaskStatus::ToDo => ' ',
        TaskStatus::InProgress => '~',
        TaskStatus::Done => 'X',
        TaskStatus::Canceled => 'C',
    }   // bez ; = návratová hodnota
}

=> (tlustá šipka) čti „pak“: „když Done, pak 'X'“. Nezaměnit s -> (tenká šipka) = návratový typ funkce.

match je výraz, stejně jako if: vrací hodnotu. Proto může stát na konci funkce bez return, nebo vpravo od let x = match ….

E0308let c: char = "X"; mismatched types: expected char, found &str. 'X' (jednoduché uvozovky) je jeden znak, "X" (dvojité) je text. V Rustu nejsou zaměnitelné.

Žádný žeton nesmí propadnout

úplnost · _ · A | B
TaskStatus::Canceled
match self.status {
TaskStatus::ToDo=>' '
TaskStatus::InProgress=>'~'
TaskStatus::Done=>'X'
TaskStatus::Canceled=>?
žeton nemá kam zapadnoutE0004

Kompilátor projde všechny možné žetony ještě před spuštěním. Když pro některý chybí přihrádka, program vůbec nepřeloží.

Třídička se nesmí ucpat. Pro každý žeton musí existovat otvor, jinak ji kompilátor nedovolí postavit.

E0004non-exhaustive patterns: TaskStatus::Canceled not covered. Přesně tohle se stalo, když jsi přidal Canceled: kompilátor tě dovedl do symbol().

_ => … je sběrný koš na všechno ostatní. Je pohodlný, ale spolkne i varianty, které přidáš později, a kompilátor už nic neřekne.

A | B => … = jedna přihrádka pro víc žetonů, | čti „nebo“. Nezaměnit se svislítky u closure |x|.

match self.status {
    TaskStatus::Done | TaskStatus::Canceled => "uzavřeno",
    _ => "otevřeno",
}
warningunreachable pattern. Dáš-li _ jako první větev, chytí všechno a přihrádky pod ní se nikdy nepoužijí.
4

matches!: branka „ano / ne“

matches!(x, Vzor)
TaskStatus::Canceled
matches!(self.status, TaskStatus::Done) je zkratka pro:
TaskStatus::Done=>true
_=>false

Jen dvě přihrádky: „tenhle vzor“ a „všechno ostatní“. Skrytý sběrný koš _ znamená, že nová varianta projde bez varování.

Turniket, ne třídička. Zajímá tě jen „pasuje, nebo ne?“ a výsledek je bool.

fn is_done(&self) -> bool {
    matches!(self.status, TaskStatus::Done)
}

! za jménem = makro, jako println!, vec! nebo dbg!. Makro se před překladem rozepíše na delší kód, tady na match se dvěma větvemi.

Kdy co: na otázky ano/ne (is_done, filter) matches!. Když každá varianta dává jiný výsledek (symbol), plný match, protože ten tě při nové variantě upozorní.

Option: krabice, která může být prázdná

Some(x) · None

Some(1)

1Option<u8>

V krabici leží lísteček s hodnotou.

None

Option<u8>

Krabice je prázdná. Pořád je to ale krabice stejného typu.

Krabice Option<u8> není číslo. Na u8 uvnitř se dostaneš, jen když nejdřív zjistíš, jestli tam vůbec je.

Nejdřív se podívej do krabice, pak sahej. V jiných jazycích je „nic“ null a zjistíš to, až když program spadne. Rust null nemá.

enum Option<T> {   // definice ve std
    None,         // prázdná krabice
    Some(T),      // krabice s hodnotou typu T
}

struct Task { ..., priority: Option<u8> }

priority: None,                   // zatím nic
self.priority = Some(priority);   // vlož do krabice

Jak číst <T>: typový parametr, „krabice na cokoliv“. Option<u8> = možná u8, Option<&Task> = možná půjčený úkol. Víc v lekci 12.

Some a None jsou tak běžné, že se píšou bez Option:: (jsou v tzv. prelude).

Varianta s daty: Some(T) ukazuje, že varianta enumu může nést hodnotu. Žeton Some má v sobě přilepený lísteček.

Vzor, který vyndá obsah

Some(p) => …
task.priority
2

nová proměnná
p2
match self.priority {
Some(1)=>"High"
Some(2)=>"Medium"
Some(3)=>"Low"
_=>"None"

Vzor Some(p) krabici otevře a obsah pojmenuje p. Vzor Some(2) navíc rovnou porovná, co uvnitř leží.

Vzor je šablona tvaru krabice. Když krabice pasuje, to, co je na místě jména, se vyndá a dostane štítek.

match tasks.get(10) {
    Some(task) => println!("Task found: {}", task.title),
    None => println!("Task not found"),
}

task ve vzoru není existující proměnná. Je to nová proměnná, která vznikne jen v této větvi. Stejný trik jako |(index, task)| u enumerate.

Vnořené vzory (z tvého priority_label): Some(1) pasuje jen na krabici, ve které je přesně 1. Na zbytek (None, Some(0), Some(4)…) je _.

E0004Bez _ by kompilátor napsal: None not covered. A s větví pro None: Some(0_u8) and Some(4_u8..=u8::MAX) not covered. Hlídá i čísla uvnitř krabice.

if let: zajímá mě jen jedna přihrádka

if let Some(p) = x { … }

Some(3)

Some(p)=>println!
jinak=>nic

Pasuje: vypíše Priority: 3.

None

Some(p)=>println!
jinak=>nic

Nepasuje: neděje se nic (nebo else).

if let je třídička s jednou přihrádkou. Všechno ostatní tiše propadne, a proto tu kompilátor úplnost nehlídá.

Podívám se do krabice, a jen když v ní něco je, s tím pracuju.

if let Some(priority) = task.priority {
    println!("   Priority: {}", priority);
} else {                         // nepovinné
    println!("   No priority");
}

Jak číst: „pokud task.priority pasuje na vzor Some(priority), tak…“. = tady není přiřazení ani porovnání. Odděluje vzor (vlevo) od hodnoty (vpravo).

v[i] vs v.get(i)
tasks: 3 úkoly (index 0, 1, 2)
0
1
2

tasks[10]

PANIKA

Sáhneš do prázdna a program spadne.

tasks.get(10)

None

Dostaneš prázdnou krabici a rozhodneš sám.

[] sahá rovnou do regálu. get ti podá krabici Option, ve které úkol buď je, nebo není.

let t = &tasks[10];         // 💥 panika za běhu

match tasks.get(10) {       // ✅ Option<&Task>
    Some(task) => println!("{}", task.title),
    None => println!("Task not found"),
}
panicindex out of bounds: the len is 3 but the index is 10. Tohle není chyba kompilátoru, program se přeloží a spadne až za běhu.

Kdy co: [i], když index určitě existuje (sám jsi ho právě spočítal). .get(i), když nemusí, třeba když číslo zadal uživatel. Přesně tak to máš v lekci 06 u done 99.

Hřiště: pusť žeton třídičkou

Vyber funkci a hodnotu. Uvidíš, do které větve hodnota zapadne a co program udělá. Tlačítkem − u větve ji vypneš (jako bys ji smazal z kódu) a uvidíš, jestli to kompilátor dovolí.

Zkus třeba: v symbol() vypni Canceled. V is_done() vypni Done. V priority_label() pusť Some(7), pak vypni _.
