Dílna na Rust

Než se dá cokoli vyrobit, potřebuješ dílnu. rustup do ní přiveze nářadí. rustc je stroj, který z textu vyrobí program. cargo je mistr dílny: řekneš mu „postav“ nebo „spusť“ a on stroj obslouží za tebe. A git je fotoalbum, kam si fotíš hotové stavy.

1Nářadí spravuje rustup.Instaluje a aktualizuje Rust (rustup update). Kompilátor i cargo přiveze najednou.
2S dílnou mluvíš přes cargo.rustc skoro nikdy nevoláš sám. Cargo ví, co a v jakém pořadí přeložit.
3target/ je výrobní hala.Všechno v ní jde kdykoli vyrobit znovu, proto do gitu nepatří (.gitignore).
1

Kdo je kdo v dílně

rustup · rustc · cargo · crate · rust-analyzer
rustupdodavatelpřiveze a aktualizuje nářadí
rustcstrojkompilátor: text → program
cargomistr dílnybuild, spuštění, balíčky. S ním mluvíš pořád.
cratebedna dílůbalíček (knihovna nebo program), ze skladu crates.io
rust-analyzerpomocník u ramenev editoru napovídá a hlásí chyby už při psaní

Zvýrazněný je ten, se kterým mluvíš nejčastěji. Ostatní pracují hlavně „za ním“.

Nemusíš umět ovládat stroj. Stačí říct mistrovi, co chceš. Cargo pak zavolá rustc se správnými parametry a ve správném pořadí.

$ rustc --version
rustc 1.95.0 (59807616e 2026-04-14)
$ cargo --version
cargo 1.95.0 (f2d3ce0bd 2026-03-21)

Jak číst --version: slova začínající -- jsou přepínače (dlouhé volby). Neříkají co dělat, ale jak. Tady: „neprováděj nic, jen vypiš verzi“.

Verze 1.95.0 se čte jako hlavní.vedlejší.oprava. Nový Rust vychází každých 6 týdnů a rustup update ho stáhne.

├── .gitignore
├── Cargo.toml
└── src/

Zeleně je, co vzniklo. Cargo k tomu rovnou založilo i git repozitář (skrytý adresář .git/).

Mistr přijde do prázdné místnosti a rozestaví základní vybavení. Hotová kostra, do které jde hned psát.

$ cd ~/Projects/todo-rs
$ cargo init --name todo
    Creating binary (application) package

Proč --name todo: bez něj by se balíček jmenoval podle adresáře, tedy todo-rs. Takhle se program jmenuje kratčeji todo a stejně se bude jmenovat i spustitelný soubor.

init vs new: cargo init zakládá projekt v adresáři, kde zrovna stojíš. cargo new nazev dělá totéž, ale nejdřív vytvoří nový adresář nazev/.

errorcargo init cannot be run on existing Cargo packages. Podruhé ve stejném adresáři to nejde, dílna už stojí.

Výrobní list: Cargo.toml

[package] · edition
[package]             # sekce: údaje o balíčku
name = "todo"         # jméno (→ target/debug/todo)
version = "0.1.0"     # verze našeho programu
edition = "2024"      # edice jazyka

[dependencies]        # sekce: cizí crates (zatím nic)

Takhle ho vytvořil cargo init. Komentáře za # jsem doplnil pro vysvětlení, v souboru nejsou.

List připíchnutý na dveřích dílny. Co se tu vyrábí, jak se to jmenuje a jaké díly se objednávají zvenku.

Formát TOML: [název] v hranatých závorkách začíná sekci. Pod ní jsou řádky klíč = "hodnota". # začíná komentář do konce řádku.

Edice (edition = "2024") je verze pravidel jazyka, ne kompilátoru. Starší kód s jinou edicí jde dál přeložit, nové edice jen přidávají nebo upravují pravidla. Máme nejnovější, 2024.

[dependencies] je zatím prázdná. Až budeme chtít hotové díly ze skladu crates.io (např. serde pro ukládání), objeví se tady.

Vstupní dveře: src/main.rs

fn main()
1fn main() {
2 println!("Hello, world!");
3}

Jediný soubor s kódem po lekci 00. Napsal ho cargo init.

Každý program má jedny vstupní dveře. Spuštění začne vždy funkcí main.

  • fn = „function“, začátek definice funkce.
  • main = jméno. Právě tohle jméno hledá Rust jako začátek programu.
  • () = funkce nebere žádné parametry. { … } = tělo funkce.
  • println! vypíše řádek. ! znamená makro, víc v lekci 01. ; ukončuje příkaz.

Proč src/: cargo čeká zdrojáky v adresáři src a binárka začíná v src/main.rs. Nemusíš mu to nikde říkat.

Výrobní linka

cargo check · build · run
kontrola chybvýroba programuuložit do target/spustit
cargo check✓———
cargo build✓✓✓—
cargo run✓✓✓✓

check zastaví linku hned po kontrole, a proto je nejrychlejší. run projde celou linku a výrobek rovnou zapne.

Tři povely pro mistra: „zkontroluj výkres“, „vyrob“ a „vyrob a zapni“.

$ cargo build
   Compiling todo v0.1.0 (/home/alex/Projects/todo-rs)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.07s
$ cargo run
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.00s
     Running `target/debug/todo`
Hello, world!

Druhý příkaz už nic nepřekládal (0.00s, žádné Compiling). Cargo si pamatuje, že se od minula nic nezměnilo.

Hotový program jde spustit i bez carga: ./target/debug/todo. ./ čti „odsud“: spusť soubor z tohoto adresáře, ne nějaký nainstalovaný v systému.

cargo build --release

  • hlídá přetečení čísel

  • pro hotový výrobek
  • (distribuce v lekci 21)

Dva různé výrobky ze stejného výkresu. Při vývoji debug, ven release. Proužky ukazují jen poměr, nejsou to měření.

Prototyp vs. sériový kus. Prototyp je hotový hned a dá se rozebírat. Sériový kus se vyrábí déle, ale je vyladěný.

$ cargo build --release
   Compiling todo v0.1.0 (/home/alex/Projects/todo-rs)
    Finished `release` profile [optimized] target(s) in 0.06s

Porovnej hlášky: `dev` profile [unoptimized + debuginfo] vs `release` profile [optimized]. Profil je sada nastavení překladu. --release přepne cargo na ten druhý.

Inspektor a uklízeč

cargo clippy · cargo fmt

cargo fmtuklízečsrovná odsazení a mezery podle standardu. Kód mění.

Po lekci 00 oba mlčí: v „Hello, world!“ není co vytknout ani uklidit.

Inspektor projde dílnu a zapíše připomínky. Uklízeč rovnou srovná nářadí do šuplíků.

$ cargo clippy
    Checking todo v0.1.0 (/home/alex/Projects/todo-rs)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.04s
$ cargo fmt
$                       # žádný výstup = hotovo

Clippy se ozve později. Už jsi od něj dostal třeba ptr_arg (lekce 05) nebo len_zero (lekce 06). Formátování při ukládání v editoru se zapíná v lekci 02.

Pomocník u ramene: rust-analyzer

rozšíření do VS Code
1fn main() {
2 let count : i32 = 5;
3 println!("{}", cuont);
cannot find value `cuont` in this scope
4}

Šedé : i32 v kódu není, dopisuje ho editor (typ proměnné). Červená vlnovka je chyba, kterou rust-analyzer našel ještě před cargo build.

Zkušený kolega, který ti kouká přes rameno. Napoví, co dál, a upozorní na chybu dřív, než stroj vůbec zapneš.

Instalace: ve VS Code rozšíření rust-analyzer (Extensions, Ctrl+Shift+X). Potřebuje nainstalovaný Rust přes rustup.

Umí tři věci, které budeš používat pořád: napovídání (doplní jméno metody), chyby při psaní (vlnovky) a typy proměnných (šedé nápovědy přímo v kódu).

Ukázka vlevo je jen ilustrace, v projektu takový kód není.

Do alba patří výkresy (zdrojáky a Cargo.*). Výrobky z target/ se nefotí, protože se dají kdykoli vyrobit znovu.

Každá lekce = jedna fotka v albu. Git si pamatuje, jak projekt vypadal po lekci 00, 01, 02… a dá se k těm fotkám vrátit (tagy lekce-NN).

$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	.gitignore
	Cargo.lock
	Cargo.toml
	src/

target/ ve výpisu chybí. Přesně to dělá řádek /target v .gitignore: „tenhle adresář nesleduj“. / na začátku znamená „v kořeni projektu“.

Cargo.lock vznikne při prvním překladu a zapisuje přesné verze použitých crates. U programu (ne knihovny) patří do gitu, a proto je v commitu lekce-00.

Hřiště: dílna v terminálu

Začínáš v prázdném adresáři ~/Projects/todo-rs. Klikej na příkazy a sleduj, co vypíšou a co přibude vpravo ve stromu souborů. Výstupy jsou opsané ze skutečného cargo 1.95.

Zkus to „špatně“: cargo build ještě před cargo init, ./target/debug/todo před buildem, nebo cargo init dvakrát. Pak dvakrát po sobě cargo build a všimni si rozdílu.
