Kartotéka úkolů

struct je šablona kartotéční karty: říká, jaké kolonky karta má a co do nich patří. Každý úkol je pak jedna vyplněná karta. V bloku impl ke kartě přidáš razítko, které vyrobí novou kartu (Task::new), a tlačítka, která s kartou něco dělají (task.complete()).

struct: šablona karty

struct Task { title: String, done: bool }
šablona (typ)

titleString

Task { … }
vyplněná karta (hodnota)
Task
title"Buy groceries"
donefalse

Šablona sama nic neobsahuje, jen říká, jaké kolonky karta má a jakého typu jsou. Data jsou až ve vyplněných kartách.

Formulář s předtištěnými kolonkami. Šablonu navrhneš jednou, vyplněných karet může být kolik chceš.

#[derive(Debug)]
struct Task {
    title: String,    // pole: jméno: Typ,
    done: bool,
}

let t = Task {
    title: String::from("Buy groceries"),
    done: false,      // pořadí polí nehraje roli
};
println!("{}", t.title);   // tečka = kolonka karty

Jak číst: title: String = „kolonka title typu String“. Dvojtečka odděluje jméno od typu, čárka odděluje pole.

Jména: typy CamelCase (Task), pole a proměnné snake_case (count_done).

E0063missing field done in initializer of Task. Karta s prázdnou kolonkou v Rustu neexistuje, výchozí hodnoty se nedoplní samy.

Karta bez fólie: t.done = true; projde.

mut patří celé kartě, ne jednotlivým kolonkám. Buď smíš přepsat všechno, nebo nic.

Bez mut je karta zalaminovaná.

let x = Task::new("b");
x.title = String::from("c");   // ❌ E0594

let mut y = Task::new("b");
y.title = String::from("c");   // ✅
E0594cannot assign to x.title, as x is not declared as mutable. Kompilátor rovnou poradí, kam mut dopsat.

Totéž platí pro Vec: tasks[1].complete() mění kartu uvnitř vektoru, proto musí být let mut tasks.

3

#[derive(Debug)]: prosvítit kartu

{:?} · {:#?} · dbg!
println!("{:?}", t); Task { title: "Test", done: false } println!("{:#?}", t); Task { title: "Test", done: false, }

{:?} vypíše kartu na jeden řádek, {:#?} (s mřížkou) přehledně pod sebe.

Rentgen pro programátora. Ukáže všechny kolonky, jak jsou. Je určený na ladění, ne pro uživatele.

#[derive(Debug)]   // atribut nad struct
struct Task { ... }

#[…] je atribut, pokyn pro kompilátor k položce pod ním. derive(Debug) = „vygeneruj sám ladicí výpis“.

{:?} vs {}: otazník = ladicí výpis (Debug). Prázdné {} = výpis pro uživatele (Display). Ten se pro vlastní typy píše ručně, k tomu se dostaneme v lekci 12.

E0277Task doesn't implement Debug. Bez #[derive(Debug)] nefunguje {:?} ani dbg!.
4

impl: razítko a tlačítka

Task::new(…) vs task.complete()

Asociovaná funkce

Task::new("…")

Razítko visí u šablony. Nepotřebuje žádnou kartu, kartu teprve vyrobí. Volá se přes :: na typu.

Metoda

task
complete() is_done()

Tlačítko je na konkrétní kartě. Pracuje s tou kartou, na které ho zmáčkneš. Volá se přes . na hodnotě.

Razítko vyrábí nové karty, tlačítko pracuje s jednou kartou. Poznáš je podle toho, jestli mají self.

impl Task {
    fn new(title: &str) -> Self { … }   // bez self → razítko
    fn complete(&mut self) { … }       // se self → tlačítko
}

let mut t = Task::new("Test");  // :: na typu
t.complete();                  // .  na hodnotě

:: vs .: :: čti „z typu“ (Task::new, Vec::new, String::from). Tečka čti „na téhle hodnotě“ (t.complete(), t.title).

Co je metoda doopravdy: funkce, které Rust tiše předá kartu jako první parametr self. t.complete() je totéž co Task::complete(&mut t).

E0061Task::complete(); → this function takes 1 argument but 0 arguments were supplied. Tlačítko bez karty nemá s čím pracovat.

Lupa, nebo tužka?

&self · &mut self
první parametrčtismív lekci
&self„půjč mi kartu na čtení“číst kolonkyis_done
&mut self„půjč mi kartu na psaní“číst i přepisovatcomplete, rename
bez self„žádnou kartu nepotřebuju“vyrobit novounew

Proč se nepíše všude &mut self? Lupa slibuje, že karta zůstane, jak byla. Ten slib pak hlídá kompilátor.

S lupou se jen díváš. S tužkou můžeš psát.

fn is_done(&self) -> bool {
    self.done                  // jen čtu
}

fn complete(&mut self) {
    self.done = true;          // přepisuju kolonku
}

fn rename(&mut self, new_title: &str) {
    self.title = new_title.to_string();
}

Jak číst: & = „půjčené“, mut = „smí se měnit“. self = „karta, na které mě zavolali“. self.done je kolonka done téhle karty.

E0594cannot assign to self.done, which is behind a & reference. Zkoušíš psát lupou: self je jen &.
E0596cannot borrow tasks as mutable, as it is not declared as mutable. Tužku nedostaneš ke kartě, která není mut.

Proč & (půjčení) a ne celá karta, rozebírá podrobně lekce 05.

Razítko new a slovo Self

fn new(title: &str) -> Self
vstup "Buy groceries"
Task::new
výstup: Self = Task
Task
title"Buy groceries"
donefalse

Razítko vyplní všechny kolonky najednou. Volající zadá jen název, done: false doplní new sama.

Razítko s předvyplněnou kolonkou. Nikdo už nemusí pamatovat, že nový úkol začíná jako nehotový.

fn new(title: &str) -> Self {
    Self {
        title: title.to_string(),
        done: false,
    }           // bez ; → tohle se vrátí
}
  • -> (tenká šipka) = „vrací“. Za ní stojí návratový typ.
  • Self s velkým S = „typ, ve kterém jsem“. Uvnitř impl Task je to Task. Malé self je konkrétní karta.
  • Poslední výraz bez ; je návratová hodnota. return se píše jen pro předčasný návrat.
  • Zkratka: když se proměnná jmenuje stejně jako pole, stačí Self { x, y } místo Self { x: x, y: y }.
E0308mismatched types: expected Task, found (). Za Self { … } je navíc ;, takže funkce nevrací nic. Kompilátor radí: remove this semicolon to return this value.
7

Vlastní sešit, nebo nápis na tabuli?

String · &str

String

sešit patří kartě"Buy groceries"

Text je vlastní. Dá se do něj psát, přidávat, mazat.

&str

tabule patří někomu jinému"Buy groceries"

Jen pohled na text, který vlastní někdo jiný. Číst ano, měnit ne.

new dostane nápis z tabule (&str) a přes .to_string() si ho opíše do vlastního sešitu (String), který zůstane v kartě.

Karta si text opíše do vlastního sešitu. Tabule se může smazat, sešit zůstane.

struct Task {
    title: String,          // pole: vlastní text
}
fn new(title: &str) -> Self {  // parametr: stačí pohled
    Self { title: title.to_string(), … }
}
kdepoužijproč
pole strukturyStringkarta vlastní svá data (&str v poli by chtělo lifetimes, lekce 14)
parametr funkce&strpřijme literál "…" i &String

Vznik: String::from("a") nebo "a".to_string() dají String. Literál "a" nebo &muj_string dají &str.

E0308Self { title: title, … } → expected String, found &str. Nápis z tabule nejde rovnou vlepit do kolonky pro sešit, musí se opsat přes .to_string().

if vrací hodnotu

if c { a } else { b }
task.is_done() == true
{ "X" }
{ " " }
[X] Clean the entire house
task.is_done() == false
{ "X" }
{ " " }
[ ] Buy groceries

Výhybka, ze které vypadne hodnota. Obě koleje musí vézt stejný typ, tady &str.

Výhybka, která rovnou vrací výsledek. Žádná pomocná proměnná se nemusí nastavovat ve dvou větvích.

println!(
    "{}: [{}] {}",
    index + 1,
    if task.is_done() { "X" } else { " " },
    task.title
);
  • Podmínka se píše bez závorek a musí být bool.
  • Hodnota větve je poslední výraz bez ;, stejně jako u funkce.
  • else je povinné, když if má vrátit hodnotu.
E0308if 1 { } → expected bool, found integer. Rust nepřevádí čísla na pravdu a nepravdu.

Indexy začínají nulou. tasks[1] je druhá karta v šuplíku.

Šuplík s kartami seřazenými za sebou.

let mut tasks: Vec<Task> = vec![
    Task::new("Buy groceries"),
    Task::new("Clean the house"),
    Task::new("Finish Rust project"),
];
tasks[1].rename("Clean the entire house");
tasks[1].complete();

let count_done = tasks.iter()
    .filter(|task| task.done)
    .count();                // 1

Vec<Task>: <…> je generický parametr, čti „Vec čeho“. tasks[i] sáhne pro kartu, mimo rozsah program spadne (panic).

Proč funguje task.done, i když task je ve filter typu &&Task: tečka sama projde všemi & až ke kartě (auto-deref). Ruční * přijde v lekci 05.

Hřiště: mačkej tlačítka na kartách

Vyber kartu a zmáčkni metodu. Každé zmáčknutí přidá řádek kódu. Když by ho kompilátor odmítl, uvidíš chybu a karty zůstanou, jak byly.

Zkus: vypni let mut tasks a zmáčkni complete(). Pak zapni „complete bere &self“. Nakonec zkus tasks[5].

    Tahák

    Ferris radí: Metoda jen čte? &self. Mění? &mut self. A poslední výraz bez ; je návratová hodnota.
