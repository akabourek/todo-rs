Úřad s přepážkami

Program je budova úřadu. Každý modul je kancelář a main.rs je vrátnice s plánem budovy. Co má kancelář na přepážce (pub), si může vyzvednout každý. Co je v zázemí, zůstává uvnitř.

mod: zápis do plánu budovy

mod list;
crate            ← main.rs, kořen
├── error        ← error.rs
├── list         ← list.rs
└── task         ← task.rs
mimo plánsrc/nesmysl.rsSoubor plný nesmyslů bez mod: cargo build projde, nikdo ho nečte.

Moduly tvoří strom a kořenem je main.rs. Ve zdrojácích je soubor, ale do programu ho přidá teprve mod.

Kancelář neexistuje, dokud není v plánu budovy. Stavba tam může stát, ale nikdo do ní nepřijde.

// src/main.rs
// „mám podmodul error, je v src/error.rs“
mod error;
mod list;
mod task;
  • mod list; se středníkem znamená „obsah je v jiném souboru“. Není to #include: nic se nekopíruje, vznikne prostor se jménem.
  • Kolikrát: pro každý soubor jednou v celém programu. Ostatní soubory ho už jen používají.
  • mod x { … } je modul přímo na místě, bez dalšího souboru.
E0432Tvoje chyba: s řádkem use error::TaskError; se z main.rs smazal i mod error;. unresolved import crate::error: soubor existuje, ale v plánu chybí. Rada crate::core::error je slepá ulička, kompilátor jen našel podobné jméno ve standardní knihovně.
E0583mod task; v list.rs: file not found for module task. Rust by hledal src/list/task.rs, protože by šlo o podmodul listu. Tady patří use.

crate::: adresa od vrátnice

crate::task::Task · :: · super::
cratezačni ve vrátnici:: taskjdi do kanceláře:: Taskvyzvedni typ
Stojím vcrate::task::Tasktask::Task
main.rs✓✓ task je můj podmodul
list.rs✓✗ v listu žádný task není

Adresa od vrátnice platí odkudkoli. Relativní adresa se hledá od místa, kde právě stojíš.

Plná adresa začíná vždycky u vrátnice. Nemusíš vědět, kde právě stojíš.

  • :: čti „uvnitř“. Znáš ho z Task::new a TaskError::ZeroIndex, u modulů funguje stejně.
  • crate je kořen celého programu, tady main.rs.
  • super:: znamená „o úroveň výš“. V list.rs by super::task::Task fungovalo taky, crate:: je čitelnější.

Celou adresu můžeš napsat rovnou do kódu, bez use:

pub fn add_task(
    tasks: &mut Vec<crate::task::Task>,
    title: &str,
) { … }
E0432use task::Task; v list.rs: unresolved import task. Kompilátor správně radí crate::task::Task.
3

use: rychlá volba na telefonu

use crate::task::Task;
telefon v list.rs
Task → crate::task::Task
TaskError → crate::error::TaskError
telefon v main.rs
Task → task::Task
io → std::io
Write → std::io::Write
telefon v error.rs
fmt → std::fmt

Každá kancelář má vlastní telefon. Zkratky se mezi nimi nepřenášejí.

Rychlá volba nikoho neteleportuje. Jen místo celého čísla stiskneš jedno tlačítko.

// src/list.rs
use crate::error::TaskError;
use crate::task::Task;

pub fn add_task(tasks: &mut Vec<Task>, title: &str) { … }
  • Poslední část cesty se stane krátkým jménem.
  • Zvyk: typy se importují přímo (Task::new), funkce se volají přes modul (list::print_tasks(&tasks)). Je hned vidět, odkud pochází. K tomu stačí mod list;.
  • Modul i proměnná se můžou jmenovat stejně: mod task; a Ok(task) => task.start() si nepřekážejí.
E0433Bez use std::fmt; v error.rs: cannot find module or crate fmt. Nepomůže, že ho měl main.rs.
unusedZbytečný use error::TaskError; v main.rs je jen varování unused import. Smaž ho, ale mod error; nech.

pub: přepážka a zázemí

pub fn · pub struct · bez pub
kancelář list · list.rs
přepážka · pub
print_tasksadd_taskstart_allfind_taskget_task
zázemí · soukromé
parse_index

parse_index volá jen get_task ve stejné kanceláři, takže ven nemusí.

Bez pub je všechno v zázemí. Na přepážku dáš jen to, co ostatní opravdu potřebují.

pub fn get_task<'a>(…) -> … {
    let n = parse_index(arg)?;   // ze zázemí, stejná kancelář
    …
}

fn parse_index(arg: &str) -> … { … }
  • pub se píše na každou položku zvlášť: typ, funkci, metodu i pole.
  • Potomci vidí nahoru: soukromou položku vidí její modul a všichni jeho potomci. Proto list.rs dosáhne na mod task;, i když nemá pub. Visí na stejném kořeni.
  • pub neumlčí never used. Binárku zvenku nikdo nevolá, takže kompilátor ví, že find_task nikdo nepoužívá.
E0603Typ nebo funkce bez pub: function print_tasks is private.
E0624Metoda bez pub: method start is private. pub struct Task metody nezveřejní.

Soukromá pole: šanon zůstává za přepážkou

title: String · fn title(&self)
kancelář task · task.rs
přepážka · pub
Tasknewtitle()is_todo()is_done()start()complete()cancel()rename()symbol()…
zázemí · soukromé
.title.status.priorityTaskStatus

TaskStatus nepotřebuje pub: je jen v soukromém poli a žádná veřejná metoda ho nevrací.

Do šanonu ti úředník sáhnout nedá. Přečte ti z něj hodnotu a změní ji podle svých pravidel.

pub struct Task {
    title: String,    // pole bez pub
    …
}

impl Task {
    pub fn title(&self) -> &str { &self.title }
    pub fn is_todo(&self) -> bool {
        matches!(self.status, TaskStatus::ToDo)
    }
}
MožnostCo to znamená
pub title: StringRychlé, ale kdokoli napíše task.title = String::new().
pub fn title(&self)Číst jde přes metodu, měnit jen přes rename. Naše volba.
E0616task.title mimo task.rs: field title of struct Task is private. Kompilátor radí a method title also exists, call it with parentheses.
privateTask { … } mimo task.rs: cannot construct Task with struct literal syntax due to private fields. Proto musí být Task::new veřejná.

Kde pub být nesmí: enum a trait

pub enum · impl fmt::Display
kancelář error · error.rs
přepážka · pub
TaskErrorMissingArgumentNotANumberZeroIndexNoSuchTaskDisplay

Varianty jsou vidět s enumem a Display všude, kde je vidět typ i trait. Zázemí tu není.

Formulář se nedává na přepážku po řádcích. Když je venku enum, jsou venku všechny jeho varianty.

use std::fmt;

pub enum TaskError {
    MissingArgument,     // bez pub
    ZeroIndex,
    …
}

impl fmt::Display for TaskError {
    // bez pub
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        …
    }
}

Proto v main.rs funguje println!("Error: {}", err), i když tam fmt ani TaskError importované nejsou.

E0449pub fn fmt nebo pub ZeroIndex: visibility qualifiers are not permitted here. Kompilátor radí remove the qualifier.

Hřiště: projdi úřadem

Pošli příkaz ukáže, kudy příkaz chodí mezi kancelářemi. Kdo na co dosáhne ukáže, co je vidět z kterého souboru. Rozbij kód ukáže, co řekne kompilátor na časté chyby. Hlášky jsou ze skutečného cargo build.

tasks
Terminál

Vyber kancelář, ve které stojíš, a pak řádek kódu. Každý řádek byl opravdu přeložený v tom souboru, uvnitř funkce s parametrem t: &mut Task.

Vyber jednu změnu. Uvidíš, který řádek se změnil (zeleně správně, červeně rozbitě), a co na to řekne cargo build. Výpisy s mnoha chybami jsou zkrácené (…).
