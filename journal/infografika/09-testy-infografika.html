Zkušebna s váhou

Za dílnou je zkušebna. Každý test je jeden zkušební stolek: vezme kus kódu, nechá ho něco vyrobit a položí výsledek na váhu (assert_eq!) proti tomu, co čekáš. Kontrolor cargo test obejde všechny stolky a dá razítko ok, nebo FAILED.

ok
1Test je funkce, která nespadne.Funkce s #[test] projde, když doběhne, a selže, když zpanikaří. Proto v ní nevadí .unwrap().
2Váha ukáže obě misky.assert_eq!(skutečná, očekávaná) při selhání vypíše left i right. Na váhu smí jen typ s PartialEq.
3Zkušebna je otevřená jen při kontrole.#[cfg(test)] mod tests se přeloží jen v cargo test. Je to dítě modulu, takže vidí i soukromé věci.

Každý stolek zkouší jednu věc. Jméno stolku je jméno funkce, ve výpisu ho uvidíš celé i s cestou.

Stolek nic nevyrábí pro zákazníka. Jen vezme vzorek, vyzkouší ho a řekne, jestli sedí.

#[test]             // nálepka: tohle je test
fn parse_index_rejects_zero() {
    // žádné parametry, nic nevrací
    assert_eq!(parse_index("0"), Err(TaskError::ZeroIndex));
}
  • #[…] je atribut, poznámka pro kompilátor k položce pod ní. Znáš ho z #[derive(Debug)].
  • #[test] = „spusť při cargo test, v normálním programu vynech“.
  • Jméno popisuje, co se ověřuje. Předpona test_ je zbytečná, to už říká #[test].
  • Jedna věc na test. Po prvním neúspěšném assert test končí a zbytek se neprovede.
item contextKontroly napsané rovnou do mod tests { } bez funkce: macro expansion ignores keyword match a the usage of assert_eq! is likely invalid in item context. Modul smí obsahovat jen položky (fn, use…), příkazy patří do těla funkce.
2

assert_eq!: váha se dvěma miskami

assert! · assert_eq! · assert_ne!
assertion `left == right` failed left: Ok(0) right: Err(ZeroIndex)

Skutečný výpis, kdyby parse_index zapomněla kontrolovat nulu. Na první pohled vidíš, co kód vrátil.

Váha neříká jen „nesedí“. Ukáže, co leží na které misce.

MakroSelže, kdyžVypíše
assert!(x)x je falsejen podmínku
assert_eq!(a, b)a != bleft a right
assert_ne!(a, b)a == bleft a right
  • ! = makro, jako println!. Při neúspěchu zpanikaří, a tím test selže.
  • Pořadí: left je první argument. Zvyk je nejdřív skutečná hodnota, pak očekávaná.
  • Číslo vlákna ve výpisu ((213925)) se při každém spuštění mění, nevšímej si ho.
assert!assert!(tasks.len() == 2) funguje, ale při selhání napíše jen assertion failed: tasks.len() == 2. Kolik úkolů tam doopravdy bylo, neuvidíš. Na porovnání proto assert_eq!(tasks.len(), 2).
3

PartialEq: co smí na váhu

#[derive(Debug, PartialEq)] · matches!
Na miscepřed lekcípo lekci
usize, &str, char✓ umí ==✓
Result<usize, TaskError>✗ E0369✓ derive u TaskError
TaskStatus✗✓ derive
Option<&Task>✗✓ derive u Task

Obal (Result, Option) jde porovnat, jen když jde porovnat i to, co je uvnitř.

Na váhu smí jen to, co má nálepku „jde porovnat“. Čísla a texty ji mají od výroby, vlastní typy ne.

#[derive(Debug, PartialEq)]
pub enum TaskError { … }
  • assert_eq! uvnitř dělá left == right (potřebuje PartialEq) a výpis {:?} (potřebuje Debug).
  • derive napíše porovnání za tebe: stejná varianta a stejný obsah. Víc traitů se odděluje čárkou.
  • Bez nálepky jde použít matches! z lekce 04. Nic neváží, jen zkouší, jestli hodnota pasuje na vzor:
assert!(matches!(
    parse_index("abc"),
    Err(TaskError::NotANumber(_))
));

_ = obsah je jedno. Nevýhoda: při selhání vypíše jen assertion failed, misky neukáže.

E0369binary operation == cannot be applied to type Result<usize, error::TaskError>. Kompilátor rovnou radí consider annotating error::TaskError with #[derive(PartialEq)].

#[cfg(test)] mod tests: zkušebna za dílnou

use super::*;
crate               ← main.rs
├── error
├── list            ← list.rs
│   └── tests       ← jen při cargo test
└── task            ← task.rs
    └── tests       ← jen při cargo test
cargo buildcargo test
modul testsnenípřeloží se
varování never used u find_taskjenení, test ji volá

Zkušebna je dítě modulu, který testuje. Proto vidí i jeho zázemí: soukromou parse_index i pole task.status.

Zkušebna se odemyká jen při kontrole. Zákazník si odnese výrobek bez ní.

#[cfg(test)]
mod tests {
    use super::*;

    fn sample_tasks() -> Vec<Task> {   // pomocná, bez #[test]
        vec![Task::new("A"), Task::new("B")]
    }

    #[test]
    fn get_task_returns_task_by_number() { … }
}
  • cfg = configuration. #[cfg(test)] = přelož jen při testech.
  • super je rodič (lekce 08), * znamená „všechno“. use se nedědí ani do vnořeného modulu, bez tohoto řádku tests nic nezná.
  • Pomocná funkce bez #[test] se sama nespustí. Každý test si z ní vezme vlastní čerstvý Vec.
never usedBez #[cfg(test)] se modul přeloží i do programu a cargo build hlásí function sample_tasks is never used: #[test] funkce v normálním buildu nejsou, takže ji nikdo nevolá.
5

Dvě pasti: stejné jméno a .clone() na &str

E0061 · E0502
v mod tests znamená get_task…
fn get_task() { … }test napsaný tady
use super::* → get_task(tasks, arg)z rodiče

Jména z use super::* mají nejnižší přednost. Položka napsaná přímo v modulu je zakryje.

Dva stolky se stejnou jmenovkou. Kontrolor zavolá ten bližší, tedy test sám.

#[test]
fn get_task() {
    let mut tasks = sample_tasks();
    get_task(&mut tasks, "2")   // volá sám sebe!
}
E0061this function takes 0 arguments but 2 arguments were supplied. Lék: test přejmenovat, třeba get_task_returns_task_by_number.
// &str → &str, pořád výpůjčka
let title = tasks[1].title().clone();
// &mut, ale title ještě čte
get_task(&mut tasks, "2")…;
E0502cannot borrow tasks as mutable because it is also borrowed as immutable. .clone() na &str zkopíruje odkaz, ne text, takže výpůjčka trvá (lekce 05). Vlastní kopie je .to_string(). Ještě lepší je napsat "B" natvrdo.
6

Dobrý test: přesný vzorek, přesná váha

natvrdo · okraje · obě strany

Očekávaná hodnota natvrdo

let title = tasks[1].title().to_string();
assert_eq!(get_task(…, "2")….title(), title);
assert_eq!(get_task(&mut sample_tasks(), "2")
    .unwrap().title(), "B");

Hodnota spočítaná ze stejných dat se rozbije spolu s kódem a test to nepozná.

Přesná kontrola

assert_ne!(Task::new("A").title.trim(), "");
assert_eq!(Task::new("A").title, "A");

„Není prázdný“ projde i se špatným titulkem.

Obě strany chování

start_all(&mut tasks);
assert!(tasks[0].is_done());
start_all(&mut tasks);
assert!(tasks[0].is_done());
assert_eq!(tasks[1].symbol(), '~');

start_all má hotový úkol nechat být a úkol ToDo spustit. Ověř obojí.

Okrajové případy

task.set_priority(9);
assert_eq!(task.priority_label(), "None");
assert_eq!(parse_index(""), Err(TaskError::MissingArgument));

Nula, prázdný text, číslo mimo rozsah. Tam se chyby schovávají nejčastěji.

Hřiště: rozbij kód a pusť kontrolora

Vyber, co v kódu rozbít, a spusť cargo test. Uvidíš, který stolek dostane razítko FAILED a co ukáže váha. Do pole můžeš napsat filtr, jako bys psal cargo test parse. Výpisy selhání jsou ze skutečného cargo test nad kódem z lekce.
