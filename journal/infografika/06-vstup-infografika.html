Cesta příkazu

Co napíšeš do terminálu, je pro program jen pásek znaků. Ten projde řadou stanic: přečíst, oříznout, rozstřihnout, roztřídit, převést na číslo, najít úkol. Poslední úsek je řada branek (if let … && let …): projdeš jen tehdy, když se otevřou všechny.

Program běží v kruhu, dokud ho něco nezastaví. Ven vedou dvě cesty a obě končí slovem break.

Kolotoč, který se točí, dokud nezatáhneš za brzdu. loop sám od sebe nikdy neskončí.

loop {
    print!("> ");
    io::stdout().flush().expect("Can't write");
    // … přečti, zpracuj …
    if bytes == 0 {
        break;      // vyskoč ze smyčky
    }
}

break ukončí nejbližší smyčku, continue skočí na začátek dalšího kola. loop je v Rustu idiomatičtější než while true.

zacykleníBez kontroly bytes == 0 po Ctrl+D read_line už nečeká a hned vrací prázdno. Kolotoč se roztočí naprázdno a donekonečna píše > Unknown command:.
2

read_line připisuje, nemaže

read_line(&mut buff)
String::new()∅
read_line: napíšeš list ⏎list\nbytes = 5
read_line znovu se STEJNÝM buff: help ⏎list\nhelp\nobsah se nahromadil
Ctrl+D∅bytes = 0 → konec vstupu

Proto let mut buff = String::new(); stojí uvnitř smyčky. Každé kolo začíná s prázdným páskem.

Lepicí páska, na kterou se jen přidává. read_line přilepí, co jsi napsal, na konec. Včetně Enteru.

let mut buff = String::new();
let bytes = io::stdin()
    .read_line(&mut buff)     // zapisuje do buff
    .expect("Can't read");     // Result → usize

&mut buff: funkce do našeho String zapisuje, proto měnitelná výpůjčka (lekce 05) a proto let mut.

Vrací Result, buď počet přečtených bajtů, nebo chybu. .expect("…") při chybě shodí program s touto zprávou, jinak číslo vybalí. Pořádně v lekci 07.

Prázdný Enter ≠ Ctrl+D: Enter vrátí 1 (je v něm \n), konec vstupu vrátí 0.

3

Ostříhat a rozstřihnout

trim · split_once · unwrap_or

S mezerou

·add Test\n trim() add Test split_once(' ') Some(("add", "Test")) unwrap_or(…) addTest

Bez mezery

list\n trim() list split_once(' ') None unwrap_or((input, "")) list""

Modrý pásek je cmd, žlutý arg. Žlutá buňka je mezera, na které se stříhá. Šedé škrtnuté znaky ustřihl trim.

Nejdřív ostříhat okraje, pak rozstřihnout na první mezeře.

let input = buff.trim();
let (cmd, arg) = input
    .split_once(' ')            // Option<(&str, &str)>
    .unwrap_or((input, ""));    // None → celé je příkaz

(a, b) je n-tice, dvojice hodnot. let (cmd, arg) = … je vzor, který dvojici rozloží do dvou proměnných, stejně jako |(index, task)| u enumerate.

.unwrap_or(x): ze Some(v) vrátí v, z None náhradní x.

tvoje chybaunwrap_or((&buff, "")) vracel neoříznutý buff, takže cmd byl "list\n". Prozradilo to , try: help vypsané na novém řádku. Oprava: uložit buff.trim() do input a dál používat jen to.

trim() vrací &str, tedy pohled do buff (slice z lekce 05). Nic se nekopíruje.

Převodník text → číslo

arg.parse::<usize>()
argparse::<usize>()parse_index
"2"Ok(2)Some(2)
"0"Ok(0)None
"abc"Err(…)None
"-1"Err(…)None
""Err(…)None
" 2"Err(…)None

usize nemá záporná čísla, proto "-1" neprojde. Mezera taky ne, parse neořezává. Proto done 2 (dvě mezery) skončí chybou.

Automat, který buď vydá číslo, nebo vrátí minci. Výsledek je Result: Ok(číslo) nebo Err(chyba).

fn parse_index(arg: &str) -> Option<usize> {
    match arg.parse::<usize>() {
        Ok(0) => None,       // nula: úkol č. 0 není
        Ok(n) => Some(n),
        Err(_) => None,      // _ = chyba mě nezajímá
    }
}

::<usize> se jmenuje turbofish (rybka ::<>). Říká, na jaký typ převádět, protože parse umí stovky typů a sám to neví.

Pořadí větví: Ok(0) musí stát před Ok(n), jinak by nulu chytilo Ok(n) (třídička z lekce 04).

Zkratka: když chybu zahazuješ celou, arg.parse::<usize>().ok() převede Result na Option.

5

Pod nulou je propast

0 - 1 u usize
-2-10123…
> done 0 thread 'main' panicked at src/main.rs: attempt to subtract with overflow

Kdyby parse_index nulu propustila, n - 1 by spadlo. Uživatel čísluje od 1, vektor od 0.

usize je pravítko, které začíná nulou. Kousek vlevo od nuly už nic není.

V debug režimu (cargo run) Rust přetečení hlídá a program zastaví. V release režimu (cargo build --release) by se číslo tiše „přetočilo“ na obrovskou hodnotu 18446744073709551615 a chyba by zůstala skrytá. Proto je lepší nulu odchytit předem.

tasks.get_mut(n - 1)   // Option<&mut Task>

get_mut je bratr get z lekce 04: podá krabici Option s měnitelnou výpůjčkou. Číslo od uživatele nikdy neindexuj přes tasks[i], protože done 99 by skončilo panikou.

Branky se zkoušejí zleva. Jakmile jedna zůstane zavřená, další se už nevyhodnocují a jde se rovnou do else.

Proměnná z branky platí doprava: v dalších brankách a v těle. V else ne, protože tam se nemusela vůbec vytvořit.

Řada turniketů na nádraží. Na peron se dostaneš, jen když projdeš všemi. Když první nepustí, k druhému se vůbec nedostaneš.

Jak číst: „když parse_index(arg) pasuje na Some(n), a zároveň tasks.get_mut(n - 1) pasuje na Some(task), tak …, jinak …“.

  • && = „a zároveň“, stejné jako u obyčejných podmínek.
  • Každá část s let je vzor jako v if let (lekce 04). Část bez let je obyčejný bool. Obojí jde míchat: tvoje první verze měla && n > 0 uprostřed.
  • Líné vyhodnocení: díky tomu je n - 1 bezpečné. Branka 2 se spustí, jen když branka 1 pustila (a parse_index nulu nepustí).
  • Je to novinka edice 2024 (Rust 1.88+). Ve starších návodech a odpovědích na internetu ji nenajdeš.
7

Jak se to psalo dřív

vnořené if let · match

Dřív: schody doprava

if let Some(n) = parse_index(arg) {
    if let Some(task) = tasks.get_mut(n - 1) {
        task.complete();
    } else {
        println!("Invalid task no!");  // 2× stejné
    }
} else {
    println!("Invalid task no!");      // 2× stejné
}

Každá další podmínka = další odsazení a další else.

Teď: jedna řada

if let Some(n) = parse_index(arg)
    && let Some(task) = tasks.get_mut(n - 1)
{
    task.complete();
} else {
    println!("Invalid task no!");      // 1× pro všechno
}

Rovné a čitelné. Ale pozor na druhou stranu mince:

daňelse neví, která branka zůstala zavřená. abc, 0 i 99 dostanou stejnou hlášku. Když chceš různé zprávy, potřebuješ vnořené větve, match, nebo vlastní chybový typ, a to je lekce 07.

Hřiště: pošli příkaz svým programem

Napiš příkaz a stiskni Enter. Uvidíš, jakými stanicemi text prošel, co bylo v každé proměnné a u start / done / cancel i které branky se otevřely. Simulace se chová jako tvůj main.rs po lekci 06.

Zkus: list s mezerami okolo, done abc, done 0, done 99, done 2 se dvěma mezerami, add bez názvu, DONE 1, prázdný Enter a nakonec Ctrl+D.
