Štítky a sklenice

Program je spíž. Hodnota je to, co leží ve sklenici, a proměnná je štítek, který na ni nalepíš. Obyčejná sklenice je zavařená, takže obsah už nevyměníš. Až mut jí dá otvírací víčko. Úkoly skladujeme buď na platu na vajíčka (pole, pevný počet míst), nebo na regálu, který jde prodloužit (Vec).

1

Šablona s okénky: println!

fn main() · println!("{}: {entry}", …)
"{}: {entry}"
{} ← index + 1 (argument za čárkou){entry} ← proměnná entry
1: Apple

Šablona má okénka. {} se vyplní dalším argumentem v pořadí, {jméno} rovnou proměnnou toho jména.

Razítko s okénky. Text je předtištěný, do okének se dosadí hodnoty.

fn main() {                       // vstupní bod programu
    println!("====== My ToDo List ======");
    println!("{}: {entry}", index + 1);
}

fn = definice funkce, main = funkce, která se spustí jako první. { } = blok kódu, příkazy končí ;.

! za jménem = makro, ne funkce. Makro se při překladu rozvine na delší kód, proto println! umí libovolný počet argumentů a šablonu kontroluje už kompilátor.

errorprintln!("{index + 1}"): invalid format string: expected }, found +. Do okénka patří jen jméno, výraz musí jít jako argument za čárkou.
2

Zavařená sklenice, nebo s víčkem?

let · let mut

let a = 5;

a
5

Zavařená. a = 6; neprojde.

let mut b = 5;

mut b
6

Otvírací víčko. b += 1; projde, teď je tam 6.

Štítek mut je vidět už na první pohled. Kdo čte kód, hned ví, které hodnoty se můžou měnit.

V Rustu je každá sklenice zavařená, dokud výslovně neřekneš, že chceš otvírací víčko.

let a = 5;
a = 6;          // ❌ E0384

let mut b = 5;
b += 1;         // ✅ b = b + 1, teď 6

let c: i32 = 5; // typ napsaný ručně
E0384cannot assign twice to immutable variable a. Kompilátor rovnou poradí: consider making this binding mutable: mut a.

+= = „přičti k tomu, co tam je“. ++ Rust nemá.

: i32 za jménem = typ (celé číslo, 32 bitů). Většinou ho psát nemusíš, kompilátor si ho odvodí z hodnoty.

Regál se prodlouží. v.push("Cherry") přidá na konec.

Tvůj seznam v lekci 01 se nemění, proto stačí pole. Ve ToDo listu budeme přidávat, a tam bude Vec.

Plato má pevný počet jamek danou už při výrobě. Regál se dá kdykoli o kus prodloužit.

let list = ["Apple", "Banana", "Cherry"]; // pole

4

Výrobna, nebo hotový kus?

Vec::new() · list.push(x)

Typ::funkce()

Vec::new() String::from("Apple")

Funkce patří typu. Často vyrábí novou hodnotu.

hodnota.metoda()

list.len() v.push("Cherry")

Metoda se volá na konkrétní hodnotě, kterou už máš.

:: mluví s výrobnou, . s hotovým kusem. Vec::new() = „výrobno Vec, udělej mi nový“. list.len() = „sezname, kolik toho máš?“

Jak číst ::: „z“. Vec::new = funkce new z typu Vec. Říká se jim asociované funkce.

"Apple" vs String::from("Apple"): první je text zapečený v programu (&str, jen ke čtení), druhý je vlastní kopie, kterou jde měnit (String). Podrobně v lekci 03.

Pás, který podává jednu věc po druhé

for (index, entry) in list.iter().enumerate()
0Apple
1Banana
2Cherry
index = 1entry = "Banana"
1: Apple 2: Banana

enumerate() nalepí na každou věc pořadové číslo od 0. Proto ve výpisu index + 1.

Pás u pokladny. for ti podá jednu věc po druhé a pro každou provede tělo cyklu.

for (index, entry) in list.iter().enumerate() {
    println!("{}: {entry}", index + 1);
}
println!("Count: {}", list.len());
  • list.iter() = pás, který postupně ukazuje na prvky (jen se dívá).
  • .enumerate() = ke každému prvku přidá číslo: dvojice (0, "Apple"), (1, "Banana")…
  • (index, entry) = rozbalení dvojice do dvou proměnných. Bez něj bys psal pair.0 a pair.1.
for entry in &list { … }   // & = jen si půjčím, list zůstane
E0382Bez & u Vec<String> cyklus seznam spotřebuje a pak list.len() hlásí borrow of moved value: list. Proč, to je lekce 05.
6

Strojek na lístečku: closure

|x| x + 1
21→
|x|x * 2
↓42

Mezi svislítky jsou vstupy (parametry), za nimi to, co strojek udělá. Jméno nemá, píše se přímo na místě, kde ho potřebuješ.

Malý strojek nakreslený na lístečku. Nemá jméno ani vlastní místo v programu, přilepíš ho rovnou tam, kde ho použiješ.

fn plus_one(x: i32) -> i32 { x + 1 } // funkce: ( )
let plus_one = |x| x + 1;             // closure: | |
let say_hi = || println!("ahoj");   // bez parametrů

list.iter().enumerate().for_each(|(index, entry)| {
    println!("{}: {}", index + 1, entry);
});

Jak číst |x| x + 1: „vezmi x, vrať x + 1“. V JavaScriptu x => x + 1, v Pythonu lambda x: x + 1.

.for_each(…) zavolá strojek pro každý prvek. Pro prosté „projdi a vypiš“ se v Rustu ale spíš píše for, a tak to máš i ve svém main.rs.

pozor| má i jiné významy: a || b = logické „nebo“, v match „nebo“ mezi vzory. Na začátku výrazu (|x| …) je to vždy closure.

Hřiště: spíž a kompilátor

Vyber, jak seznam vytvoříš, a klikej na příkazy. Každé kliknutí přidá řádek kódu. Když by ho kompilátor odmítl, uvidíš chybu a seznam zůstane, jak byl. Spustit for projde seznam krok po kroku jako tvůj main.rs.
