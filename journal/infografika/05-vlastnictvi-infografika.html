Kdo drží krabici?

Představ si každou hodnotu v Rustu jako krabici (třeba jeden Task nebo celý Vec<Task>) a každou proměnnou jako štítek se jménem, který je ke krabici přivázaný. Celé vlastnictví a půjčování se pak dá vysvětlit tím, kdo krabici drží, kdo se do ní smí dívat a kdo v ní smí přerovnávat.

Štítek t platí jen do konce bloku. S ním zmizí i krabice a všechno v ní (i String s názvem).

Krabice patří tomu, na koho je napsaná. Vlastník za ni odpovídá. Když odchází (konec bloku), vezme krabici s sebou a vyhodí ji.

{
    let t = Task::new("Nákup"); // t vlastní Task
    println!("{}", t.title);
}                               // t končí → Task se uvolní

Proto Rust nepotřebuje garbage collector. Vždy přesně ví, kdo krabici drží a kdy ji pustí.

Krabice se nezkopírovala. Jen změnila majitele. a teď drží prázdné ruce.

Předáš krabici někomu jinému. Už ji nemáš, tak do ní nemůžeš ani nahlédnout.

let a = Task::new("Test");
let b = a;                // krabice přešla z a na b
println!("{}", a.title);  // ❌ E0382
E0382borrow of moved value: a. Snažíš se použít štítek, od kterého už krabice odešla.

Proč to Rust hlídá: kdyby krabici měli a i b, oba by ji na konci zkusili vyhodit (dvojité uvolnění). Stejně funguje předání do funkce: print_tasks(tasks) s parametrem tasks: Vec<Task> si krabici vezme a main už ji nemá.

3

Lísteček vs. kopírka

Copy · .clone()

Copy: lísteček s číslem

5x
5y

let y = x; číslo se prostě opíše. Oba mají svůj lísteček.

Clone: kopírka na krabice

a
b

let b = a.clone(); vznikne druhá, úplně samostatná krabice.

Malé věci se opisují samy, velké se musí kopírovat výslovně.

u8, i32, bool, char jsou typy Copy. Jsou malé a levné, takže je Rust při přiřazení zkopíruje a původní proměnná platí dál.

String, Vec ani tvůj Task Copy nejsou. Chceš-li dvě nezávislé krabice, zavoláš .clone(). Je to vidět v kódu, protože to stojí práci a paměť.

#[derive(Debug, Clone)]   // Task umí .clone()
struct Task { ... }       // …a proto i TaskStatus musí mít Clone

let b = a.clone();        // ✅ a i b mají svou krabici

Nahlížení: sdílená výpůjčka

&tasks
tasks
Vec<Task>
print_tasks
find_task
first

Krabice zůstává u vlastníka. Dívat se smí kolik lidí chce, protože čtením nic nerozbijí.

Pustíš ostatní, ať se podívají dovnitř. Nic nevyndají, nic nepřidají. Až se dodívají, krabici máš pořád ty.

fn print_tasks(tasks: &[Task]) { ... } // jen čte

print_tasks(&tasks);   // půjčím k nahlédnutí
print_tasks(&tasks);   // ✅ tasks pořád patří mně

Jak číst &: ve výrazu (&tasks) „udělej referenci na tasks“, v typu (tasks: &[Task]) „tohle je reference“. U tečky Rust referenci rozbalí sám: píšeš task.title, ne (*task).title (co znamená ta *, je v kroku 6).

5

Půjčení s klíčem: výhradní výpůjčka

&mut tasks
mut tasks
Vec<Task>
add_task
print_tasks first

Klíč má jen jeden člověk. Čtenáři mezitím čekají venku, protože by mohli vidět napůl přerovnanou krabici.

Dáš někomu klíč a necháš ho v krabici přerovnávat. Dokud ho má, nikdo jiný do krabice nesmí, ani ty sám.

fn add_task(tasks: &mut Vec<Task>, title: &str) {
    tasks.push(Task::new(title));
}

let mut tasks = vec![ ... ];   // krabice musí jít otevřít
add_task(&mut tasks, "New task"); // &mut i při volání

Dvě podmínky: vlastník musí být let mut (krabice se dá otevřít) a &mut píšeš i při volání. Na první pohled tak vidíš, kde se data můžou změnit.

6

Hvězdička: jdi po štítku ke krabici

*r (dereference)

r: samotný štítek

r
count

Typ &mut u8. Říká jen, kde krabice je.

*r: obsah krabice

r
1count

Typ u8. Číslo, které v krabici leží.

& a * jsou opaky: & k hodnotě vyrobí štítek, * se po štítku vrátí zpátky k hodnotě.

Hvězdička znamená: nechci štítek, chci to, na co ukazuje. Jdeš po šňůrce až ke krabici a pracuješ s jejím obsahem.

let mut count: u8 = 0;
let r = &mut count;     // r = štítek s klíčem na count
*r += 1;                // ✅ změň obsah krabice
println!("{}", count);  // 1

r += 1;                 // ❌ E0368: přičíst ke štítku?
E0368binary assignment operation += cannot be applied to type &mut u8. Číslo nepřičteš ke štítku, jen k tomu, co je v krabici.

Jak číst: *r čti „hodnota, na kterou ukazuje r“. Hvězdička stojí vždy před jedním jménem. Nezaměnit s násobením a * b, které má hodnotu na obou stranách.

Kdy ji psát: při přiřazení a počítání přes referenci (*r = 5;, *r += 1;). U tečky to Rust udělá sám, proto píšeš task.title a task.start() místo (*task).title. Sám to zvládne i println!("{}", r).

E0507let t = *task_ref; s Task nejde, protože hvězdička by krabici vyndala z půjčky a odnesla. U Copy typů (let n: u8 = *r;) se obsah jen opíše, a to projde.
7

Mnoho čtenářů, nebo jeden zapisovatel

borrow checker

❌ Překrývají se

let first = &tasks[0]; add_task(&mut tasks, "…"); println!("{}", first.title);

✅ Jedna po druhé

let first = &tasks[0]; println!("{}", first.title); add_task(&mut tasks, "…");
žije výpůjčka & (first)žije výpůjčka &mut

Výpůjčka trvá do posledního použití reference, ne do konce bloku. Stačí přehodit řádky.

Zatímco se někdo dívá, nesmí nikdo přerovnávat.

E0502cannot borrow tasks as mutable because it is also borrowed as immutable. Někdo se pořád dívá (first se ještě použije), a ty už chceš klíč.

Proč je to nebezpečné doopravdy: push může vektor při nedostatku místa přestěhovat jinam v paměti. first by pak ukazoval na místo, kde krabice už není.

E0499cannot borrow tasks as mutable more than once at a time. Dva klíče od jedné krabice nejsou.

0
1

Krabici z regálu si můžeš prohlédnout. Odnést si ji smíš, až když ji z regálu vyndáš.

Metoda se self (bez &) si krabici vezme celou a rozbalí ji. To jde jen s krabicí, kterou opravdu vlastníš.

fn into_title(self) -> String { self.title }

tasks[0].into_title();          // ❌ E0507: patří vektoru

let task = tasks.remove(0);     // vyndám, teď je moje
let title = task.into_title();  // ✅ krabice spotřebována
E0507cannot move out of index of Vec<Task>. Nemůžeš odnést, co máš jen půjčené.

Názvy metod to napoví: as_… a to_… berou &self (krabice zůstane), into_… bere self (krabici spotřebuje).

9

Výpůjčka nesmí přežít krabici

'a (lifetime)
TaskUVOLNĚNO
r

Vlastník odešel a krabici vyhodil. Štítek r by ukazoval do prázdna, a to Rust nedovolí.

Nemůžeš se dívat do krabice, která už neexistuje.

let r;
{
    let t = Task::new("Nákup");
    r = &t;
}                          // t končí, krabice zničena
println!("{}", r.title);   // ❌ E0597
E0597t does not live long enough. Krabice žije kratší dobu než výpůjčka.

Tohle hlídá zápis 'a ve tvém find_task<'a>(tasks: &'a [Task], …) -> Option<&'a Task>: „vrácený pohled je půjčený z tasks a nesmí ho přežít.“ Podrobně v lekci 14.

Pohled na kus regálu

&[Task]
0
1
2
3
&tasks &tasks[1..3]

Vec<Task> je regál. Slice &[Task] je pohled na souvislou řadu krabic, celou nebo jen na kus.

Funkci, která jen čte, je jedno, čí regál to je. Stačí jí ukázat řadu krabic.

fn print_tasks(tasks: &[Task])       // čte: stačí pohled
fn start_all(tasks: &mut [Task])     // mění krabice, ne jejich počet
fn add_task(tasks: &mut Vec<Task>, …) // přidává: potřebuje celý regál

Proto ti clippy u &Vec<Task> hlásil ptr_arg. Slice umí jen krabice, které už na regálu stojí. Přidat novou (push) jde jen přes &mut Vec.
